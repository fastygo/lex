Jev is TypeSafe's first public System One model, which is a fundamentally new class of AI models, architected with new training and sampling methods researched by TypeSafe for the last two years.

Jev evaluates typed questions and returns structured decisions optimized for programmatic usage, not human readers. Jev tells you when it’s uncertain with a confidence value you can use in code. The TypeSafe model isn’t trained to please human beings; it's trained to be reliable, especially when there isn't a correct answer. Furthermore, each decision is a calibrated probability, so similar inputs give similar outputs.

Jev can understand natural language as well as leading frontier reasoning models like Opus 4.8 and Terra, but Jev cannot generate string responses. The only response you'll get from Jev are machine-native structured decisions, which means that the structured output is not converted from a string response, like they are with Pydantic and other well-known structured output providers. Jev's structured outputs are an intentional product of Jev's architecture. In other words, Jev is not an LLM wrapper. To emphasize, Jev is not a generative chat model, so it cannot output strings or hold a conversation with you.

To get answers from Jev, you must define the shape of the answer in your question. (Refer to the primitives section of the TypeSafe documentation.) You have to provide context. It's kind of like writing multiple choice questions.

Jev is a decision model: you send a state (the content to judge) and a map of named questions. Every question is one of three primitives. Choice picks one option from a list you define (up to 255 options) and returns the winner, a probability for every option, and a confidence value. Score places the state on an ordered scale of 2 to 10 levels you describe in words and returns a probability-weighted mean of the level numbers, so the value can land between two levels, plus a legend, probabilities, and confidence. Noul answers a yes/no question with one number from 0 to 1: the probability that the answer is yes. Noul has no separate confidence field, because that probability already is the certainty measure: near 1 is a confident yes, near 0 a confident no, and 0.5 is maximum uncertainty.

Choice and Score confidence is a statistic computed from the probability distribution the answer already gives you. Mass concentrated on one option or level gives a high number. Mass spread across several gives a low one. Nothing asks the model how sure it feels. TypeSafe trained Jev with Reinforcement Learning for Calibrated Decisions (RLCD), which optimizes for epistemically honest probabilities rather than preferred text.

Use Choice when your code switches on a named option. Use Score when it compares against a numeric cutoff or sorts a list. Use Noul when it gates a single branch. Do not build a Choice with options like “low”, “medium”, and “high” when you want a Score: you lose the ordering and the in-between value. Do not build a Score out of unordered categories, because the probability-weighted mean of things that have no order is a meaningless number. Prefer Noul over a two-option Choice. Add an “other” or “none of the above” option when a Choice taxonomy might not cover everything. Ask the most explicit, narrow, specific, atomic questions you can; several questions in one request are evaluated independently and in parallel against the same state, so adding questions barely changes latency.

A successful Jev answer cannot contain a value outside the options or levels you supplied. The model never invents a fourth category. Question IDs are for your code and are not sent to the model, so write the complete question in instructions. Jev answers in a single parallel pass rather than generating tokens one by one. It cannot write prose, summaries, or code. TypeSafe documents that it is unreliable at counting, arithmetic, and treating dates as ordered quantities.
